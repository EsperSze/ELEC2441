Reducing CPI below 1

The system throughput of an ARM processor is 1 CPI after the pipeline is filled. A further reduction of the CPI can be attained by

  1. increasing the clock rate of the processor;
  2. increasing the total number of instructions available in the processor;
  3. increasing the largest difference between the latencies of all pipeline stages;
  4. increasing the total number of pipeline stages;
  5. none of the above.
Answer & comprehensive explanation

Correct answer: E — none of the above. This follows the ideal single-issue pipeline model described in the lecture.

1. What is a pipeline?

Instruction processing is divided into stages so different instructions can be processed simultaneously at different stages. ARM7 uses Instruction Fetch (IF), Instruction Decode (ID), and Datapath Execution (EX).

Assume each stage takes one cycle, one new instruction enters per cycle, and there are no stalls or flushes.

2. What does “filled” mean?

In cycle 3, instruction 1 is executing, instruction 2 is decoding, and instruction 3 is being fetched. All stages are occupied: the pipeline is full. From the end of cycle 3, one instruction completes each cycle while new instructions continue arriving.

The first two cycles do useful fetching and decoding; nothing has completed yet. This does not mean the CPU is doing nothing.

3. What does single-issue mean?

At most one instruction is issued into execution per cycle. In this simple model, think of one new instruction entering each cycle. Several instructions can still be in progress. “Single-issue” is supplementary terminology: LT6 section 6.3 describes the behaviour without explicitly using this label.

Pipeline depth means the number of stages. Issue width means how many instructions can be issued per cycle. More stages do not automatically increase issue width.

4. Latency and CPI are different

Each individual instruction takes three cycles to pass through this pipeline: latency = three cycles. But completed instructions emerge one per cycle after filling: steady-state CPI = 1.

\[\text{Average CPI}=\frac{\text{Total clock cycles}}{\text{Number of instructions executed}}\]

5. Why can average CPI exceed 1?

Starting from an empty three-stage pipeline, the five instructions in the table take seven cycles in total.

\[\text{Total clock cycles}=\text{Number of instructions executed}+2\]
\[\text{Average CPI}=\frac{\text{Number of instructions executed}+2}{\text{Number of instructions executed}}\]

Five instructions: 7/5 = 1.4 CPI. One hundred instructions: 102/100 = 1.02 CPI. The average approaches 1 as the initial two-cycle overhead becomes less significant.

For an initially empty ideal pipeline with one-cycle stages and one instruction entering each cycle:

\[\text{Total clock cycles}=\text{Number of instructions executed}+\text{Number of pipeline stages}-1\]

These formulas assume no stalls or flushes. Use number of instructions executed, not “size of the instruction set.” An instruction set is the collection of supported operations, such as ADD and LDR.

6. Why the question says “after the pipeline is filled”

It specifies steady-state operation, excluding the initial filling delay. The pipeline is already completing one instruction per cycle. More instructions can bring the whole-program average closer to 1, but cannot make this ideal single-issue steady-state CPI less than 1.

7. Evaluate the options

OptionWhy it does not reduce CPI below 1
A: Higher clock rateEach cycle becomes shorter. Instructions per second can increase, but cycles per instruction remains 1.
B: More instructions availableDoes not increase the number completed per cycle or issue width. A longer stream only reduces the relative importance of initial overhead.
C: Greater differences between stage latenciesCreates imbalance. The slowest stage constrains the pipeline clock period; imbalance does not enable multiple completions per cycle.
D: More stagesMay allow a shorter clock period, but the simple pipeline still ideally completes one instruction per cycle.

Further context: CPI below 1 requires more than one instruction to complete per cycle on average, as can occur with a multiple-issue/superscalar processor. None of the listed changes alone provides this capability.

Remember: fewer seconds per instruction does not necessarily mean fewer cycles per instruction.
